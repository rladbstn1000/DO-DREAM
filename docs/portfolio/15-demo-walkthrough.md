# 15. 샘플 체험과 로컬 통합 웹 시연

## 서버 없는 공개 샘플 체험 (showcase)

[공개 샘플 체험](https://rladbstn1000.github.io/DO-DREAM/)을 열면 Docker·가입·설정 입력 없이 원래 교사 웹과 휴대폰 안의 학생 앱을 둘러볼 수 있다. 실제 AI 답변·로그인·서버 저장을 시연하는 화면은 아니다. 로컬에서는 `fe-web`에서 `npm run build:showcase` 후 `npm run preview:showcase`를 실행하고 출력된 주소를 연다. 원본 UI·표시 보완과 공개 검증은 [21 결과](21-original-ui-showcase-results.md), 최초 구현과 배포 이력은 [19 결과](19-static-showcase-results.md)·[20 결과](20-publication-and-pages-results.md)에 구분했다.

1. 시작 화면의 **교사 체험**에서 자료 목록과 학급을 둘러본다. **물의 여행**을 열면 원래 도구 배치의 편집기로 이동한다. 편집·임시 저장·공유는 현재 탭의 샘플 상태만 바꾼다.
2. 시작 화면의 **학생 앱 체험** 또는 상단 **학생 앱**을 선택한다. 서재의 **물의 여행**을 열고 재생 방식 화면에서 **처음부터 듣기**를 선택해 본문을 읽는다. **설정**에서 글자 크기를 바꿀 수 있다.
3. 플레이어의 노란 **질문하기**를 누르고 **말하기**에서 예시 질문을 고른 뒤 **확인**을 누른다. 준비된 예시 답변과 **참고 구간 보기**의 연결 문장을 확인하고 **닫기**나 Escape로 돌아온다. 등록되지 않은 자유 질문에는 예시 질문 안내만 표시한다.
4. **뒤로**를 두 번 눌러 재생 방식 화면으로 돌아간다. 휴대폰 내부를 아래로 스크롤하면 **저장 목록**과 마지막 메뉴 **퀴즈 풀기**가 나타난다. 모든 메뉴가 처음 화면에 보일 필요는 없다.
5. **퀴즈 풀기**에서 첫 문제를 열고 답을 직접 입력한다. **다음 문제**로 두 번째 답을 입력한 뒤 **채점하기**를 선택한다. **음성으로 답하기**는 마이크 대신 예시 답 선택을 열며, 지정된 허용 답안과 비교하는 샘플 규칙으로 판정한다.
6. 결과에서 새로고침해 같은 풀이를 확인한다. **다시 풀기**는 새 회차를 시작한다. 최근 10개 풀이 기록을 탭에 보관하며, 퀴즈 한 번으로 모든 자료의 학습을 완료 처리하지 않는다.
7. 상단 **교사 웹** → **1학년 1반** → **체험 학생**에서 이 탭의 질문과 풀이를 살펴본다. 질문 목록의 **물의 여행**을 열면 대화 이력을 확인할 수 있다. 실제 학생·학급 기록이나 다른 탭·기기와의 동기화가 아니다.
8. 상단 **초기화**로 showcase 소유 상태만 지운다. 다른 앱의 저장소 상태는 유지한다.

로컬 인수에서는 같은 산출물을 `/`와 `/DO-DREAM/`에서 확인했다. 공개 사이트는 `/DO-DREAM/`에 있으며 중첩 화면은 `#/app/library`, `#/app/material/water-journey/result`, `#/teacher/student/demo-student`처럼 해시 안에 둔다. 해당 탭에 결과가 없으면 먼저 풀이하도록 안내한다. 이전 `/learn`·본문·퀴즈 해시는 대응 앱 화면으로 이동하고, 옛 선택형 결과는 새 서술형 결과와 구분해 안내한다.

말하기와 음성 답하기는 실제 마이크를 사용하지 않는다. 본문 듣기는 기기의 로컬 한국어 음성이 있을 때만 제공한다. 실제 청취·VoiceOver·네이티브 앱 검증은 NOT_RUN이며, 브라우저 자동 검사와 구분한다.

## 실제 백엔드가 동작하는 로컬 통합 시연 (phase1)


팀 구현 이후의 개인 개선 4단계 시연 순서다. 기존 서비스·영속 데이터 위에서 직접 작성한 샘플 2개를 체험한다. 이 실제 백엔드 통합 모드는 로컬 전용이며 실제 외부 AI는 호출하지 않는다. 구현 계약은 [13 설계](13-student-web-design.md), 실제 실행 결과·검토한 캡처·미실행 항목은 [14 결과](14-phase4-results.md)에 기록한다. 아래 절차와 미배포·미실행 판정은 당시 실행 범위이며, 위 공개 정적 체험의 검증과 구분한다.

현재 5단계 소스에서는 같은 화면 흐름을 새 `student-web-phase5-v1` 로컬 교재와 `demo-phase5-v1@local.dodream.invalid` 합성 교사로 실행한다. 아래4단계 캡처·결과·이메일은 당시 증거로 보존한다. 현재 증거는 `.local/phase5/`에 남는다. 공급자 준비 코드가 추가됐지만 실제 호출 승인·키가 없어 요청0회이며 **REAL_AI_INTEGRATION=NOT_RUN**이다. 현재 실행과 승인 후 재개 명령은 [02 실행 지침의 5단계 절](02-local-runbook.md#5단계-공급자평가-준비와-승인-후-재개), 결과는 [17](17-phase5-results.md)을 따른다.

## 1. 준비와 시작

저장소 루트에서 실행한다. Docker Desktop/Compose와 Python3가 필요하다. 학생 자동 인수 검사에는 기존 Chrome과 Playwright 실행 환경을 사용한다. 사용자 Chrome 프로필·기존 탭은 사용하지 않는다. 새로운 장비의 첫 환경 생성·추가형 스키마 준비는 [02 실행 지침](02-local-runbook.md)을 먼저 따른다. 기존 `.env`를 가져오거나 DB·볼륨을 초기화하지 않는다.

```bash
cd /Users/yoonsu/Desktop/projects/DO-DREAM
python3 scripts/local/manage.py check
python3 scripts/local/manage.py config
python3 scripts/local/manage.py build
python3 scripts/local/manage.py demo-up
python3 scripts/local/manage.py demo-prepare
python3 scripts/local/manage.py status
```

`demo-up`은 서버의 local 전용 체험 기능을 명시적으로 켠다. 일반 `up`의 기본값은 체험 비활성이다. 체험을 다시 열 때도 `demo-up`을 사용한다. 별도 개발 서버나 프런트엔드 flag만으로 활성화하지 않는다.

`demo-prepare`는 전용 합성 교사로 실제 로그인해 준비 API를 호출하고, 원장·Celery·Chroma를 거쳐 두 발행 자료가 읽을 수 있게 되었는지 기다린다. 준비를 두 번 호출해 식별자와 논리 개수가 같은지도 확인한다. 샘플 파일·교재·문제를 삭제하거나 매번 새로 만들지 않는다. 이미 발행된 샘플을 직접 편집했다면 이 명령이 편집본을 원문으로 덮어쓰지는 않는다.

기본 접속: [학생 체험 시작](http://127.0.0.1:15173/demo). 웹 포트를 바꾼 경우 `.local/env`에 설정한 `WEB_PORT`에 맞춘다. 포트를 다른 프로세스가 쓰면 종료하지 말고 실행 지침의 포트 조정 절차를 따른다.

## 2. 학생 체험 순서

1. `/demo`에서 직접 작성 자료와 로컬 체험 안내를 확인하고 **학생 체험 시작**을 누른다. 이미 로그인되어 있다면 해당 계정을 유지한다. 다른 역할로 바꾸려면 먼저 명시적으로 로그아웃한다.
2. 자료함에서 **물의 여행 학습 시작**을 선택한다. 자료의 실제 준비 상태가 사용 가능이어야 한다.
3. **얼음과 물**을 읽고 **다음 단원**으로 **하늘로 올라가는 물**을 확인한다. 글자 크기를 바꾸어도 본문·버튼이 잘리지 않는지 살펴본다.
4. 질문 칸에 `물이 공기 중으로 나가는 것을 무엇이라고 하나요?`를 적고 **질문 보내기**를 누른다. 로컬 대역 답변과 실제 자료 검색 표시를 확인한다. 검색 결과에 따라 발췌가 달라질 수 있으므로 특정 문장을 맞추는 품질 시연으로 설명하지 않는다.
5. 답변의 **참고 자료 보기**를 누른다. 서버가 현재 권한과 같은 원본 버전을 재확인한 제목·버전·본문 발췌를 읽고 닫는다. 없는 페이지 번호나 단원 위치를 추측해서 설명하지 않는다.
6. 마지막 단원까지 읽고 원하면 **학습 완료**를 누른다. 스크롤만으로 완료 저장이 일어나지 않는다는 점을 확인한다.
7. **퀴즈 풀기**로 이동한다. 물이 차가워졌을 때의 모습과 액체가 기체로 바뀌는 이름을 본문에서 찾아 자기 답안으로 입력한다. 제출 전에는 서버 정답을 내려받지 않는다.
8. **제출하기**를 누르고 **퀴즈 결과**에서 서버가 저장한 당시 문제·내 답안·정답·피드백을 확인한다. local 채점은 외부 모델의 교육적 해설 품질을 보여주는 기능이 아니다.
9. 결과 화면을 새로고침한다. 같은 attempt 결과를 서버에서 다시 확인한다. 새 풀이를 하려면 **새 풀이 시작**을 명시적으로 선택한다.
10. **자료함**으로 돌아가 **생활 속 분리배출**도 같은 방식으로 읽는다. 예시 질문은 `분리배출 전에 용기는 어떻게 준비하나요?`다.

읽어주기를 시연할 경우 **본문 듣기**를 사용자가 직접 누른다. 기기의 로컬 한국어 voice가 있을 때만 시작하고 **듣기 일시정지**·**듣기 계속**·**듣기 중지**를 확인한다. 음성이 없으면 제한 안내를 보여주고 텍스트 학습을 계속한다. 원격 voice로 전환하거나 음성 모델을 설치하지 않는다.

이번 검증의 **TTS_AUDIBLE_CHECK=NOT_RUN**, **SCREEN_READER_MANUAL=NOT_RUN**이다. 합성 speech API 단위검사와 실제 Chrome의 voice/API 관측은 소리를 직접 들은 검사 또는 VoiceOver 사용 검사와 다르다. 브라우저 API 관측 결과는 [14 결과](14-phase4-results.md)를 따른다. 실제 청취·VoiceOver·브라우저 확대는 별도 수동 점검이 필요하며 320 CSS px 검사를 실제 확대 검사나 접근성 인증으로 설명하지 않는다.

## 3. 담당 교사에게 결과 보여주기

학생 화면을 유지하면서 **별도의 독립 브라우저 context**에서 [기존 교사 로그인](http://127.0.0.1:15173/)을 연다. 같은 context의 다른 탭은 쿠키·인증 저장소를 공유하므로 교사·학생 동시 시연에 사용하지 않는다.

- 교사 이메일: `demo-phase4-v1@local.dodream.invalid`
- 비밀번호: 준비 시 생성된 `.local/env`의 `LOCAL_TEACHER_PASSWORD`. 사용자가 로컬에서 확인해 입력하며 터미널 출력·시연 문서·화면 캡처·Git에 복사하지 않는다.

기존 **로그인 하기** 흐름으로 로그인한 뒤 `DO:DREAM 웹 체험 합성 학교`의 전용 합성 학급을 연다. 학생 화면에 표시된 `체험 학생 N`을 선택하고 해당 자료의 퀴즈 결과를 확인한다. 기존 `/student/:studentId`가 이 교사용 상세 화면이며 새 학생 학습 URL로 바뀐 것이 아니다. 학생 이름·자료·제출 결과가 일치하는 실제 화면을 보여준다.

## 4. 오류와 복구를 설명하는 방법

| 화면 안내 | 시연 중 할 일 |
|---|---|
| 자료가 없거나 준비 중 | 실제 공유·색인 상태를 확인한다. 접수 상태를 사용 가능이라고 말하지 않는다. |
| 응답 유실 또는 결과 불명 | 퀴즈 화면의 **같은 제출 확인**으로 저장된 key/body 또는 attempt를 재확인한다. 새 제출로 우회하지 않는다. |
| 확인된 실패·UNKNOWN | 서버가 허용할 때만 **채점 재시도**를 선택한다. UNKNOWN은 이전 결과가 불명임을 확인하며 최대 3세대를 유지한다. |
| 문제가 변경됨 | **최신 문제로 새 풀이 시작**을 선택하고 최신 문제를 읽는다. 기존 답안·버전을 몰래 바꾸지 않는다. |
| 자료 버전이 변경됨 | **새 자료로 대화 시작**을 명시적으로 선택한다. 옛 대화 기록은 보존된다. |
| 공유 권한 회수 | 본문·참고 자료·결과를 캐시로 우회하지 않는다. 담당 교사가 현재 공유 상태를 확인한다. |
| 탭 저장소 사용 불가 | 안전한 제출 복구를 보장할 수 없다는 안내에 따라 제출을 중단한다. |
| 로컬 음성 없음 | 음성 설치·원격 voice로 전환하지 않고 글을 읽어 체험을 계속한다. |

채팅은 응답을 잃으면 서버에 질문 또는 답변이 남았을 수 있다. **대화 기록 확인** 후 사용자가 직접 재전송을 결정한다. 채팅의 자동 exactly-once나 브라우저 종료·기기 변경 후 퀴즈 복구를 보장하지 않는다.

## 5. 재현 가능한 학생 웹 인수 명령

앞의 빌드·시작·샘플 준비를 마친 후 짧은 AT 서버도 명시적인 체험 설정으로 준비한다. 일반 서비스의 AT 수명을 바꾸지 않는다.

```bash
DODREAM_DEMO_ENABLED=true python3 scripts/local/manage.py auth-test-up
python3 scripts/local/manage.py student-web
```

`student-web`은 독립 Chrome context에서 페이지 열기 → 체험 시작 → 본문/단원 → 질문/참고 자료 → 퀴즈 제출 → 결과/새로고침 → 교사 결과 확인을 한 실행으로 검사하는 명령이다. 실제 실행된 세부 항목과 결과는 해당 실행 증거와 14 문서를 확인한다. 준비·DB 확인용 API 검사, 실제 서비스 장애, 브라우저 오류 응답 주입은 정상 UI 조작과 구분하여 기록한다. 첫 정상 흐름이 실패하면 같은 원인의 후속 검사를 쌓지 않고 원본 실패를 보존한다.

증거는 `.local/phase4/results/`, 인수 실행의 준비 파일은 `.local/phase4/browser-ui/`에 남긴다. `phase4-acceptance-<runId>.json`은 실행별 상태·종료 코드와 시작/종료 앱 소스 식별자를 기록한다. 이전의 중단된 실행에서 일부 PASS를 모아 한 실행 PASS라고 하지 않는다. 최종 인수 실행 중 앱 소스를 바꾸지 않는다.

화면 증거는 직접 작성한 합성 자료로 실행한 실제 Chrome 캡처다. 이미지 생성물이나 mockup이 아니며 로컬 대역 안내를 숨기지 않는다. 캡처와 검증 상태는 [14 결과](14-phase4-results.md)에서 함께 확인한다.

## 6. 종료와 다시 체험하기

```bash
python3 scripts/local/manage.py stop
```

처음부터 실행 중인 자체 서비스가 있었다면 시작 snapshot에 맞춰 이번에 시작한 서비스만 복구한다. 다른 프로젝트를 중지·복원하지 않는다. 샘플·새 학생 기록·영속 볼륨은 남으며 `down -v`, prune, DB/Chroma reset을 사용하지 않는다.

다시 열 때는 `demo-up` → `demo-prepare` 후 `/demo`에 접속한다. 같은 fixture 버전은 재사용되며 같은 visitor는 같은 체험 학생으로 돌아온다. 방문자 생성 상한에 도달하면 안내를 따르고 기존 기록을 삭제해 우회하지 않는다.

시연이 증명하는 범위는 로컬 학생 웹과 실제 서버 저장·권한·검색 연결이다. **REAL_AI_INTEGRATION=NOT_RUN**, **PUBLIC_DEPLOYMENT_READY=false**이며 실제 AI 품질·모바일 전체 실행·VoiceOver·실제 음성 청취는 각각 수행한 증거가 있을 때만 별도로 설명한다. 다음 모델 연결·평가·공개 배포에는 자동 착수하지 않는다.

## 7. 5단계 모드와 평가 준비를 설명하기

학생 화면의 embedding·answer·grading 표시를 각각 읽는다. 로컬 교재는 로컬 공급자이며, 일부 연결만 준비되거나 모드를 확인하지 못한 상태를 전체 실제 AI라고 소개하지 않는다. 신규 live 평가 자료는 승인된1536차원 색인 작업이 실제로 성공하기 전까지 준비 중일 수 있다. 기존8차원 교재와 대화·풀이 기록은 유지한다.

이번에는 실제 공급자 답변·비용 시연을 하지 않았다. [고정 합성 평가 도구](../../scripts/evaluation/README.md)의 `python3 scripts/evaluation/phase5.py review`는 답변·참고 구간·평가 기준을 나란히 보는 로컬 표를 만들며, 실제 관측이 없는 답변과 사람 검토는 NOT_RUN이다. 이 화면을 모델 정확도나 교육 효과 검증으로 소개하지 않는다.

향후 명시 승인과 예산·키·격리 검증이 모두 준비되면 02 문서의 순서로 live 세션을 열고 승인된 새 자료에서 작은 학생 흐름만 확인한다. 같은 풀이 재조회에서 추가 채점 호출이 없는지 원장과 연결한다. 기존55개 오류 검사를 live로 반복하지 않는다. 평가와 시연을 마치면 `python3 scripts/local/live_ai.py close`로 호출 경로를 닫고 키 없는 로컬 회귀를 수행한다. 실제 음성·OCR·외부 파일 저장소·공개 배포 준비는 별도다.
